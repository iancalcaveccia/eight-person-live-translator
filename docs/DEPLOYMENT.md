# Deployment

Three pieces, three providers:

| Piece | Where | Notes |
|---|---|---|
| Web app + control plane API | **Vercel** project linked to this GitHub repo | functions in `fra1` (Frankfurt), daily cron `/api/cron/cleanup` |
| Translator worker | **LiveKit Cloud Agents**, region `eu-central` (Frankfurt) | long-running Python; never on Vercel |
| Group/membership authority | **Postgres** (Neon via Vercel Marketplace, EU region) | `DATABASE_URL` is server-only |

## Secrets and where they live

| Variable | Vercel | LiveKit agent | Notes |
|---|---|---|---|
| `LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` | yes | auto-injected by LiveKit Cloud | create an API key in the LiveKit dashboard |
| `GEMINI_API_KEY` | **no** | yes | Google AI Studio, paid tier (free tier data may be used for training) |
| `OPENAI_API_KEY` | **no** | optional | backup for `en`/`es` targets only |
| `DATABASE_URL` | yes | no | created by the Neon integration |
| `INTERNAL_API_SECRET` | yes | yes (same value) | generated by `configure-cloud.ps1` |
| `APP_SECRET`, `CRON_SECRET`, `HOST_ACCESS_CODE` | yes | no | generated by `configure-cloud.ps1` |
| `CONTROL_PLANE_URL` | no | yes | the production URL of the web app |

No secret uses a `NEXT_PUBLIC_` prefix; the build was checked for leaked names
(`docs/TEST_REPORT.md`).

## Steps

1. **LiveKit Cloud**: create (or pick) a project at https://cloud.livekit.io,
   create an API key, then on this machine run `lk cloud auth` and approve it in
   the browser.
2. **Gemini**: create an API key at https://aistudio.google.com/apikey on a
   project with billing enabled; set a budget alert in Google Cloud.
3. Put the LiveKit URL/key/secret and the Gemini key in `translator/.env.local`
   (gitignored).
4. **Database**: Vercel dashboard → the project → Storage → Create Database →
   Neon → region Frankfurt (eu-central-1) → connect to Production and Preview.
5. Run:

   ```bash
   powershell -ExecutionPolicy Bypass -File scripts\configure-cloud.ps1 -AppUrl https://<project>.vercel.app
   ```

   It sets all Vercel variables (sensitive), creates the LiveKit agent in
   `eu-central` with its secrets, deploys the web app to production, checks
   `/api/health` and prints the host access code once (also saved to
   `.secrets/host-access-code.txt`, gitignored).
6. Open the URL on two phones and run the first rows of
   `docs/DEVICE_TEST_PLAN.md`.

Later deploys: pushing to `main` redeploys the web app automatically;
`cd translator && lk agent deploy` redeploys the worker.

## Verifying a deployment

- `GET /api/health` → `{"database":true,"livekit":true,"internalApi":true,"hostCode":true}`
- Create a gathering with the host code; open the invite on a second device.
- `lk agent status` shows the worker running; `lk agent logs` shows
  `translation router ready` when a room starts.
- An uninvited request to `/api/gatherings/<id>/token` must return 401.
